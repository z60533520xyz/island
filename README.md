# 🗳️ 大選戰 Online

台灣選舉主題的多人策略網頁桌遊。佈局服務處、開闢掃街路線、動員樁腳，搶先拿到 10 票當選！開一個房間、把連結傳給朋友就能開始玩，玩家之間透過 **WebRTC 點對點連線**，不需要架設遊戲伺服器。

線上試玩：https://z60533520xyz.github.io/island/

## 快速開始

```bash
npm start          # 等同 node serve.mjs 8080，不需要安裝任何套件
# 開啟 http://localhost:8080/
```

ES module 不能直接用 `file://` 開啟，所以需要一個靜態伺服器。要讓不同電腦的朋友加入，把整個資料夾部署到任何靜態網站空間就行（GitHub Pages、Netlify、Cloudflare Pages…），**一定要用 HTTPS**，因為瀏覽器只允許在安全來源上使用 WebRTC。

1. 輸入名字 →「建立新房間」，會拿到一組 5 碼的房間代碼與邀請連結
2. 朋友開啟邀請連結（或輸入代碼）→ 加入
3. 2~6 人到齊後，房主按「開始遊戲」。2~4 人使用標準地圖，5~6 人會自動改用大地圖

在同一台電腦上測試：開**另一個視窗**（不要直接複製分頁，複製分頁會沿用同一個玩家身分），貼上邀請連結即可。

### 房間設定（房主在大廳設定）

| 設定 | 說明 |
|---|---|
| 隨機座位順序 | 預設開啟：開始時打亂玩家順序，決定誰先開始與回合順序（顏色也跟著順序分配） |
| 佈局階段每輪放置掃街路線 | 預設 1 條；可以改成 2 條，第 2 條必須接在本輪的服務處或第 1 條掃街路線上 |
| 特別建設階段 | 只適用於 5~6 人，預設開啟 |

## 遊戲規則

| 元素 | 說明 |
|---|---|
| 資源 | 📄 文宣、🪧 看板、🙋 志工、🍱 便當、💰 資金；🥀 艱困選區不產出 |
| 掃街路線 | 📄🪧，連接你的據點；最長且至少 5 段者得「最長掃街路線」+2 票 |
| 服務處 | 📄🪧🙋🍱，1 票；彼此至少相隔兩段路 |
| 競選總部 | 由服務處升級，🍱×2 💰×3，2 票，產出加倍 |
| 錦囊卡 | 🙋🍱💰；樁腳 14、民調領先 5、掃街拜票 2、募款餐會 2、媒體壟斷 2（大地圖：20／5／3／3／3） |
| 🕵️ 黑函 | 擲出 7 時，資源超過 7 張者棄一半；當前玩家把黑函投向一個選區（停止產出），並從旁邊自選一位對手挖角 1 張指定資源 |
| 👥 樁腳 | 錦囊卡之一：移動黑函並挖角；黑函必須在自己的服務處或競選總部旁才能動員。累積 ≥3 位且最多者得「最強樁腳網」+2 票 |
| 人脈 | 據點位於人脈旁，可與公庫 3:1（任意）或 2:1（指定資源）交易；一般為 4:1 |

- 佈局階段採蛇形順序，第二間服務處會立即獲得周圍選區的資源
- 每回合：擲骰產出 → 交易 → 建設 → 結束。一旦建設或購買錦囊卡，本回合就不能再交易，未成交的提案自動取消（掃街拜票的免費路線不算）
- 所有人的資源都是公開資訊；錦囊卡只顯示張數
- 錦囊卡每回合限用一張，當回合買的不能用
- 公庫庫存不足時：只有一人需要則給剩下的，多人需要則都不發
- 在自己的回合拿到 10 票即當選（隱藏的民調領先卡會自動計入）
- 5~6 人：30 個選區的大地圖（2 個艱困選區、11 個人脈），公庫每種資源 24 張；每個回合結束後進入特別建設階段，其他候選人依序可以建設或買卡，但不能交易

## 架構

```
index.html        畫面骨架（首頁 / 大廳 / 遊戲）
css/style.css
js/geometry.js    地圖幾何（標準 19 個選區／大地圖 30 個選區）與隨機地圖產生
js/engine.js      規則引擎：純資料、沒有 DOM 依賴，可以在 Node 裡測試
js/net.js         PeerJS 包裝：HostNet / ClientNet
js/ui.js          SVG 地圖與側邊欄的渲染、按鈕事件
js/main.js        房主／客戶端的訊息處理、畫面切換、斷線重連
serve.mjs         本機開發用的靜態伺服器
test/             自動化測試
```

**房主權威（host-authoritative）**：規則引擎只在房主的瀏覽器上執行。
- 客戶端 → 房主：`{t:'hello', name, token}`、`{t:'action', action}`、`{t:'chat', text}`
- 房主 → 客戶端：`{t:'lobby'}`、`{t:'state', view}`、`{t:'error'}`、`{t:'chat'}`、`{t:'kick'}`

每位玩家收到的 `view` 都經過 `viewFor()` 處理：資源是公開資訊；其他人的錦囊卡只會顯示張數，牌庫順序也不會傳出去，所以沒辦法透過開發者工具偷看。

連線使用 [PeerJS](https://peerjs.com/) 的免費公共配對伺服器（`0.peerjs.com`）交換連線資訊，建立連線後資料直接在瀏覽器之間傳送。

## 斷線與恢復

- **客戶端**重新整理或斷線後，會用同一個分頁的身分（存在 sessionStorage）自動回到原本的座位
- **房主**每次狀態改變都會存進 localStorage；如果房主關掉頁面，重新開啟首頁可以按「恢復上次的對局」，用同一組房間代碼重新開房，其他玩家重新連線即可接著玩
- 如果有玩家離線卡住遊戲（輪到他、或他需要棄牌），房主可以按「代為行動」自動完成目前的步驟

## 限制

- 房主離線時遊戲會暫停，直到房主恢復房間
- 部分企業網路或對稱式 NAT 環境沒辦法直接建立 P2P 連線。遇到這種情況需要在 `js/net.js` 的 `iceServers` 加入 TURN 伺服器

## 測試

```bash
npm test
```

- `test/simulate.mjs`：用隨機機器人跑 300 局 2~6 人的完整對局，每一步都檢查資源總數守恆與棋子數量，並驗證非法動作會被拒絕、隱藏資訊、最長掃街路線被截斷等情況
- `test/render.mjs`：用簡化的 DOM 替身，在 3 人與 6 人的各種遊戲狀態與對話框下執行所有渲染路徑
- `node test/snapshot.mjs 6 board.svg`：輸出一張隨機地圖的 SVG，方便目視檢查
